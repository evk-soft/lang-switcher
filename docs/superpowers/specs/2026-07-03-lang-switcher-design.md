# Дизайн-спецификация: lang-switcher

Дата: 2026-07-03. Статус: на ревью у владельца проекта.

## Проблема

Пользователь постоянно работает в двух раскладках (русская/английская) и в момент начала набора не знает, какая активна. Стандартный индикатор Windows в трее находится вне зоны внимания. Существующие решения либо заброшены (Punto Switcher), либо решают другую задачу (автопереключение), либо платформенно-одиноки (Input Source Pro — только macOS).

## Продукт

Резидентная утилита, которая делает текущую раскладку видимой в точке внимания пользователя:

1. **Транзиентный бейдж** (режим по умолчанию): при смене раскладки возле курсора мыши появляется бейдж «RU»/«EN» и исчезает через настраиваемые ~1.5 с.
2. **Режим следования** (опция): бейдж виден постоянно и следует за курсором. Сохранённый режим восстанавливается при начальном чтении раскладки, без звука.
3. **Якорь-каретка** (M2, progressive enhancement): если позицию текстовой каретки удаётся определить — бейдж показывается у каретки; иначе автоматический откат к курсору; при недоступности того и другого — фиксированный угол экрана.
4. **Звуковая подсказка** (вкл. по умолчанию): различимые короткие сэмплы для RU и EN при переключении; громкость/отключение в настройках.
5. **Трей**: иконка с текущей раскладкой, меню (режим, звук, автозапуск, настройки, выход).

Вид бейджа настраивается: текст (RU/EN), флаг, цветовая метка. По умолчанию — текст на цветной подложке (различимо периферийным зрением, без политической нагрузки флагов; флаги — опция).

## Нефункциональные требования

- ~0% CPU в простое (событийная модель, ADR-0003); ~5–15 МБ RSS; бинарник 1–4 МБ; мгновенный старт при автозапуске.
- Оверлей: поверх всех окон, click-through, не крадёт фокус, корректен на mixed-DPI мониторах.
- Платформы: Windows 11 (M1–M2) → macOS (M3) → Linux X11 полноценно / Wayland деградированно (M4).

## Технология

Чистый нативный Rust (аудит июня 2026 → ADR-0001). Cargo workspace с портами/адаптерами (ADR-0002): ядро `switcher-core` без OS-зависимостей; трейты в `switcher-platform` (`LayoutMonitor`, `PointerTracker`, `CaretLocator`, `OverlayWindow`, `Autostart`, `SoundPlayer`); адаптеры `switcher-windows`/`-macos`/`-linux`; оболочка `switcher-app` (tray-icon + muda, rodio, egui-настройки по требованию).

## Архитектура и поток данных

Потоки хуков ОС → каналы плоских событий → ядро-автомат `(state, event) -> (state, effects)` → эффекты (показ/перемещение/скрытие бейджа, звук, обновление трея). Детали техник по каждой ОС — [overview.md](../../architecture/overview.md), оверлей Windows — ADR-0004.

Ключевые правила ядра:

- Дедупликация: рантайм подтверждает текущую раскладку при обработке уведомления, ядро схлопывает повторы текущего HKL. Быстрый возврат A → B → A не подавляется ([ADR-0011](../../architecture/adr/0011-authoritative-layout-snapshots.md)).
- Выбор якоря: caret > cursor > fixed — по доступности, с автопонижением.
- Таймер скрытия — единственный таймер ядра, взводится только при видимом транзиентном бейдже.

## Конфигурация

TOML в платформенном каталоге (`directories`), сериализация serde, версия схемы + миграции. Поля: режим (transient/follow), якорь (auto/cursor/fixed), вид бейджа, длительность показа, звук (вкл, сэмплы, громкость), автозапуск, язык интерфейса настроек.

## Обработка ошибок

- Отказ любого адаптера (нет разрешения Accessibility, недоступен D-Bus и т.п.) — деградация возможности, не падение: приложение продолжает с меньшей функциональностью и показывает причину в настройках/трее.
- Паника в потоке хука перезапускает поток с backoff; повторные падения отключают источник и логируются.
- Логи: tracing + файл в каталоге данных, уровень настраивается.

## Тестирование

- Ядро — test-first, таблично (событие × состояние × конфиг), включая дедупликацию и оркестрацию подписок.
- Адаптеры — за трейтами, потребители на моках; сами хуки — ручной smoke-чеклист (скил `platform-api-work`).
- Перед коммитом: скил `quality-gates` (fmt, clippy -D warnings, tests) + workflow `rust-adversarial-review`.

## Дорожная карта

| Веха | Содержание |
|---|---|
| M1 — Windows MVP | трей, 3 источника событий раскладки, транзиентный бейдж у курсора, звук, автозапуск, конфиг |
| M2 — полировка | якорь-каретка, egui-настройки, режим следования, инсталлятор + winget |
| M3 — macOS | TIS-события, NSPanel-оверлей, SMAppService |
| M4 — Linux | X11 полноценно; Wayland: фикс-бейдж + D-Bus, честная деградация |

Первый спринт M1 — прототип двух главных рисков: layered click-through оверлей на mixed-DPI и связка трёх источников событий раскладки.

## Риски

1. Windows-детекция — «whack-a-mole» краевых случаев (elevated/UWP/консоль): закрыто комбинацией источников + взводимый фолбэк (ADR-0003).
2. Каретка ненадёжна везде (терминалы, игры, Electron) — только progressive enhancement, никогда не обещается.
3. Wayland не даёт ни позиции курсора, ни протокола раскладки — деградация зафиксирована в спеке заранее.
4. Экосистемный дрейф Rust-крейтов (winit mid-refactor) — критический путь не зависит от winit; версии пиннятся.
