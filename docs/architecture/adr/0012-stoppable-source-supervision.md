# 0012. Супервизор источников останавливается явно и учитывает все возможности потока

Дата: 2026-09-07. Статус: accepted.

## Контекст

ADR-0007 задаёт повторные запуски, но первоначальный внутренний хелпер возвращал
только `JoinHandle` и ждал backoff через `sleep`. Канал событий не закрывается,
пока его клоны живут в адаптерах; он не может быть сигналом завершения. Кроме того,
поток раскладки по ADR-0009 обслуживает две возможности, а хелпер принимал одну.

## Решение

Хелпер принимает статический список возможностей и возвращает RAII-владельца
потока. Владелец при завершении устанавливает флаг остановки, отправляет сигнал
в отдельный канал, будит очередь Win32 и выполняет join. Очередь создаётся до
публикации идентификатора потока. Backoff ждёт канал с timeout и прерывается сразу.
Насос проверяет флаг перед блокирующим ожиданием и между сообщениями; периодического
таймера проверки остановки нет. Тело источника создаёт и освобождает свои нативные
ресурсы на этом же потоке и использует насос непосредственно.

Ошибка насоса возвращается вызывающему коду. При повторном запуске все возможности
потока получают `Degraded`; после исчерпания бюджета — `Off`. Успешная установка
каждого источника отдельно публикует его состояние. Невозможность установить один
из независимых хуков не должна уничтожать работающий второй хук.

## Рассмотренные альтернативы

- Ожидать разрыва общего канала: адаптеры сами удерживают его отправителей.
- Оставить непрерываемый `sleep`: штатный выход может задержаться на четыре секунды.
- Разнести shell и foreground по потокам: не решает общий контракт остановки и
  увеличивает число потоков вопреки принятой карте ADR-0009.

## Последствия

Внутренний API супервизора меняется до появления продуктовых потребителей.
Контракт проверяется тестами прерывания backoff, выхода из заблокированного насоса
и отчётов по нескольким возможностям. Порты приложения не получают Win32-хэндлы.
