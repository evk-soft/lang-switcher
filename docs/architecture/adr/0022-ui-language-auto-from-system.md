# 0022. Язык интерфейса по умолчанию берётся из языка интерфейса Windows

Дата: 2026-09-09. Статус: accepted.

## Контекст

ADR-0021 задал механизм переводов, но не источник языка. У приложения есть три
разных «языка», и их легко перепутать:

1. язык ввода — что сейчас набирает пользователь; читается из HKL и показывается
   на бейдже;
2. язык интерфейса Windows — на каком языке система показывает свои меню;
3. региональные форматы — даты, числа, валюта.

Прежняя реализация умела только первое. Поле конфига `ui_language` имело
значение по умолчанию `"ru"` и жёсткий список из двух допустимых значений: `fr`
сбрасывался в `ru` с предупреждением, то есть добавление шестого языка означало
правку валидатора в ядре.

## Решение

- `ui_language` принимает `"auto"` либо канонический языковой тег Unicode.
  Значение по умолчанию для новых установок — `"auto"`.
- Нормализация в `switcher-core` выполняется через `unic-langid`: `"EN"` → `"en"`,
  `"zh-hans"` → `"zh-Hans"`, `"ru_RU"` → `"ru-RU"`. Неразбираемое значение
  сбрасывается в `"auto"` с предупреждением.
- Ядро **не** проверяет, есть ли для тега каталог. Валидный, но неподдерживаемый
  тег сохраняется как есть, а оболочка при подборе локали отступает на `en`.
  Так список поддерживаемых языков остаётся в одном месте (ADR-0021), а конфиг
  пользователя не портится при откате на версию с меньшим набором каталогов.
- Уже сохранённые явные `"ru"` и `"en"` — канонические теги, они переживают
  обновление без изменения смысла и без предупреждений.
- Источник системного языка — новый порт
  `switcher_platform::ports::UiLanguages::preferred() -> Result<Vec<String>, PlatformError>`.
  Через границу порта проходят только обычные строки.
- Windows-адаптер вызывает
  [`GetUserPreferredUILanguages`](https://learn.microsoft.com/en-us/windows/win32/api/winnls/nf-winnls-getuserpreferreduilanguages)
  с `MUI_LANGUAGE_NAME` по документированной схеме из двух вызовов: первый с
  `pwszLanguagesBuffer = NULL` и `pcchLanguagesBuffer = 0` возвращает нужный
  размер, второй заполняет буфер. Буфер — упорядоченный список строк,
  разделённых нулём и завершённый двумя нулями; адаптер разбирает его целиком и
  не полагается на `pulNumLanguages` как на длину.
- `GetKeyboardLayout` для этой задачи не используется: он отвечает на вопрос
  «что набирают», а не «на каком языке показывать». Региональные форматы
  (`GetUserDefaultLocaleName`) тоже не используются: пользователь с русской
  Windows и американскими форматами дат должен видеть русский интерфейс.
- Подбор локали: точный тег → тот же язык с другим регионом или письменностью →
  `en`. Системный список обходится по порядку, побеждает первый язык, для
  которого нашёлся каталог.
- Отказ порта не мешает работе: приложение берёт `en`, а причина попадает в лог.
  Отдельная `Capability` для этого не заводится — язык интерфейса не является
  теряемой во время работы возможностью в смысле ADR-0007, чтение выполняется
  один раз при старте и при каждом переключении на «Как в системе».
- Смена языка интерфейса из трея применяется немедленно: перерисовываются
  подписи меню, подсказка и строки состояния. Она не воспроизводит звук смены
  раскладки и не показывает бейдж — это не событие ввода.

## Рассмотренные альтернативы

- Оставить список допустимых значений в ядре: каждый новый каталог требовал бы
  правки `switcher-core` и ломал бы конфиги при откате версии.
- Хранить `Option<String>` вместо строки `"auto"`: в TOML отсутствие поля уже
  означает «значение по умолчанию», поэтому `None` не отличалось бы от
  «пользователь явно выбрал системный язык».
- `GetUserDefaultUILanguage` (единственный LANGID вместо списка): теряет
  порядок предпочтений пользователя и не различает письменности.
- Определять язык по раскладке: у пользователя с русской раскладкой и
  английской Windows интерфейс менялся бы вместе с набором текста.

## Последствия

`switcher-app` получает зависимость от `unic-langid` (через ядро — тоже), а
`switcher-windows` — от уже включённой возможности `Win32_Globalization`.

Появляется обязательство тестировать подбор локали отдельно от Fluent: список
`["fr-CA", "de-DE"]` должен выбрать `fr`, список `["ja-JP"]` — `en`, пустой
список — `en`.

Проверка на реальной системе с не-русским языком интерфейса в alpha не
выполняется: у разработчика одна машина. Поведение `"auto"` проверяется
модульно на подставном порте, а на реальной Windows проверяется только явный
выбор языка из трея. Это записано в ограничениях alpha.
