# 0002. Cargo workspace c портами и адаптерами (hexagonal)

Дата: 2026-07-03. Статус: accepted.

## Контекст

Три ОС с принципиально разными API, при этом доменная логика (state machine раскладки, выбор якоря, конфиг) общая. Нужно развивать платформы независимо, тестировать ядро на любой машине и оставить путь к смене UI-оболочки (например, добавить Tauri для настроек).

## Решение

Workspace из шести крейтов: `switcher-core` (домен, `#![forbid(unsafe_code)]`, без OS-зависимостей), `switcher-platform` (только traits + типы событий), `switcher-windows`/`-macos`/`-linux` (адаптеры; единственные крейты с `unsafe`), `switcher-app` (оболочка и wiring). Ядро — чистая функция `(state, event) -> (state, effects)`; адаптеры общаются с ядром каналами, передавая плоские данные.

## Рассмотренные альтернативы

- **Один крейт с `#[cfg(target_os)]`** — быстрее стартовать, но платформенный код прорастает в домен, ядро нельзя собрать/тестировать без заглушек, границы размываются.
- **Динамические плагины (dlopen)** — не нужны: набор платформ фиксирован, цена сложности не окупается.

## Последствия

- (+) Ядро тестируется unit-тестами на 100% без ОС; новая платформа = новый крейт-адаптер.
- (+) `unsafe` локализован и проверяется ревью только в адаптерах.
- (−) Церемония: тип события и трейт на каждую платформенную способность; принимаем как цену тестируемости.
