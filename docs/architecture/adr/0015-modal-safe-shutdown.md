# 0015. Завершение трея доставляется оконным сообщением

Дата: 2026-09-07. Статус: accepted.

## Контекст

Трей выполняет `TrackPopupMenu` на главном потоке. Пока меню открыто, системный
модальный цикл забирает сообщения сам; обычный `PumpWaker` без HWND может быть
поглощён без дренажа канала команд. Поэтому запрос остановки ядра не должен
ждать, пока пользователь закроет меню.

Это соответствует описанию Microsoft: [thread messages теряются в модальных циклах](https://devblogs.microsoft.com/oldnewthing/20050426-18/?p=35783),
а [WM_QUIT завершает их с передачей намерения наружу](https://devblogs.microsoft.com/oldnewthing/20050222-00/?p=36393).

## Решение

Главный поток после PMv2 создаёт `QuitWindow` и владеет им до завершения worker.
Клонируемый `QuitSignal` содержит отзываемый числовой адрес окна; никаких Rust-указателей
или HWND-обёрток через поток не передаётся. `TraySender::send(Shutdown)` сначала
кладёт команду в канал, затем делает `PostMessageW` этому окну. Его wndproc вызывает
`PostQuitMessage` на главном потоке, в том числе внутри модального цикла.

Весь native-код остаётся в `switcher-windows`, wndproc имеет unwind-границу.
После остановки отправителей Drop отзывает адрес и уничтожает окно на его потоке.
Обычные команды трея продолжают использовать канал и `PumpWaker` (ADR-0009).

Основной поток отправляет отдельный stop ядру, ждёт подтверждение до пяти секунд,
затем делает join. Подтверждение отправляется после Drop/join адаптеров и TSF.
Отказ трея или panic идут через тот же cleanup. Истечение предела явно логируется
и возвращает ошибку; это аварийная ветка, без обещания завершившегося join.

## Рассмотренные альтернативы

- Только `PostThreadMessage`: системный модальный цикл не знает наш канал команд.
- Периодический опрос канала на главном потоке: расходует ресурсы в простое и
  не устраняет необходимость взаимодействия с системным модальным циклом.
- Передать callback с Rust-состоянием: усложняет владение и реентрантность без необходимости.

## Последствия

Появляется одно дополнительное скрытое окно без таймера. Отправители обязаны
завершиться раньше владельца окна. Native-регрессия исполняет вложенный цикл
без custom drain, получает WM_QUIT и передаёт его наружу; отдельный таймер
ограничивает только длительность теста при регрессии. Сам `TrackPopupMenu`
интерактивно ещё требует проверки по smoke-чеклисту.
