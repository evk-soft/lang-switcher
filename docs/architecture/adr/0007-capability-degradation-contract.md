# 0007. Деградация — учёт возможностей на уровне оболочки; ядру сообщается только факт автозапуска

Дата: 2026-08-25. Статус: accepted.

## Контекст

Дизайн-спека требует: «Отказ любого адаптера — деградация возможности, не падение: приложение продолжает с меньшей функциональностью и показывает причину в настройках/трее» и «Паника в потоке хука перезапускает поток с backoff; повторные падения отключают источник и логируются».

Реализовать это было нечем: в `switcher-platform` существовал только `PlatformError(String)` (с нулём потребителей во всём воркспейсе), ни события, ни эффекта, несущего отказ, не было, а у `LayoutMonitor` не было способа остановить или перезапустить источник.

Отдельная конкретная дыра: `Event::SetAutostart(enabled)` безусловно писал `cfg.autostart = enabled` и эмитил `[ApplyAutostart, PersistConfig]` **одним батчем**. При отказе записи в реестр конфиг оказывался на диске с утверждением, которого ОС не подтвердила.

## Решение

Линия, на которой держится вся минимальность: **конфиг хранит намерение пользователя, карта возможностей хранит реальность ОС.** `sound.enabled = true` при мёртвом звуковом устройстве — корректный конфиг: пользователь хочет звук, ОС не может. Ядро продолжает эмитить `Effect::PlaySound`, приложение делает no-op и показывает причину. Единственное поле, где намерение и реальность совпадают по определению, — `autostart`: он не пожелание, а **зеркало значения в реестре**.

**1. Учёт возможностей — плоские данные, потребитель только `switcher-app`.**

```rust
// switcher-platform::events
pub enum Capability {
    LayoutShellHook, LayoutForegroundHook, LayoutTsf,
    Pointer, Caret, Overlay, Sound, Autostart,
}
impl Capability {
    pub const fn key(self) -> &'static str;          // "layout.tsf" — стабильный ключ для логов и тестов
    pub const fn is_layout_source(self) -> bool;     // трей агрегирует три избыточных источника в одну строку
}
pub enum CapabilityState { Ok, Degraded, Off }
pub struct CapabilityReport {
    pub capability: Capability,
    pub state: CapabilityState,
    pub code: &'static str,       // "registry_write_denied", "restart_budget_exhausted"
    pub detail: String,           // одна строка для трея; английская (см. последствия)
}

pub enum PlatformEvent { /* … */ CapabilityChanged(CapabilityReport) }
```

`PlatformError` получает стабильный машинный код: `PlatformError { code: &'static str, detail: String }`. Код авторизует адаптер — иначе оболочке пришлось бы придумывать код для «сбоя записи в реестр», то есть тащить Win32-знание в шелл.

Событие идёт **тем же каналом**, что и остальные `PlatformEvent`: адаптеры уже владеют одним `Sender`, а порядок важен — `LayoutChanged`, пришедший после `CapabilityChanged(LayoutTsf, Off)`, валиден (сработал другой источник) и не должен переупорядочиваться.

`CapabilityChanged` **не передаётся** в `Engine::handle`. Оболочка держит `CapabilityMap` и на каждое изменение пишет `warn!` со стабильным ключом, обновляет тултип трея (агрегат: «⚠ 2 функции недоступны») и текст неактивного пункта меню «Состояние» с построчными причинами. Тултип трея обрезается на 128 UTF-16 единиц (проверено в исходниках `tray-icon`), поэтому в тултипе — агрегат, а подробности — в меню.

**2. Автозапуск — двухфазный round-trip, повторяющий уже доказанную схему `QueryAnchor → AnchorResolved`.**

```rust
Event::SetAutostart(enabled)            => vec![Effect::ApplyAutostart(enabled)]   // конфиг НЕ трогаем
Event::AutostartApplied { requested, ok } => если !ok  -> vec![Effect::SyncTrayMenu]
                                            иначе     -> обновить cfg + vec![Effect::PersistConfig]
```

Новый `Effect::SyncTrayMenu` = «пересинхронизировать галки трея из `Engine::config()`, **не** записывая файл»: пользователь щёлкнул галку, а ОС отказала — галку надо отщёлкнуть назад. «Оптимистично + корректирующее событие» технически неспасаемо: `PersistConfig` летит в том же батче, неверное значение успевает попасть на диск раньше коррекции.

Тот же `Event` бесплатно закрывает сверку на старте: приложение читает `Autostart::is_enabled()`, и при расхождении с конфигом **реестр побеждает** — в ядро подаётся `AutostartApplied { requested: actual, ok: true }`, что чинит и конфиг, и галку. Если `is_enabled()` вернул ошибку — `CapabilityChanged(Autostart, Off)` и пункт меню становится неактивным.

Дедупа в `SetAutostart` нет намеренно (в отличие от `on_set_mode`): режим — радиокнопка, чей источник истины конфиг; автозапуск — чекбокс, чей источник истины реестр, а реестр мог разъехаться (чистильщик, ручная правка, другая копия приложения), и повторный клик обязан его перезаявить.

**3. Перезапуск потоков хуков — супервизор внутри адаптерного крейта.**

Владелец — `switcher-windows`, не оболочка: setup потока стопроцентно OS-специфичен (регистрация класса, message-only окно, `RegisterShellHookWindow`, `SetWinEventHook`, `CoInitializeEx` + TSF-синк), а универсальный супервизор в шелле потребовал бы фабрику-замыкание в портовой поверхности — прямой запрет «через границы потоков только плоские данные».

Расписание: `catch_unwind` вокруг тела потока, backoff **250 / 1000 / 4000 мс**, сброс бюджета попыток после **60 с** непрерывной работы, после исчерпания трёх попыток — `CapabilityChanged(cap, Off, "restart_budget_exhausted")` и выход. Транзиент (перезапуск `explorer.exe`, роняющий shell-hook) восстанавливается с первой-второй попытки; поток, умерший трижды за пять секунд, от упорства не оживёт. Сброс бюджета — та часть, которую обычно забывают: без него процесс, живущий неделю, накопит несвязанные сбои и заглушит здоровый источник.

Ядру знать не надо, и это доказуемо: поведение ядра при мёртвом источнике раскладки побитово идентично поведению при тихом источнике — событий нет, решений нет.

**`panic = "abort"` в профилях сборки запрещён** — иначе `catch_unwind` не сработает и весь супервизор становится мёртвым кодом. Сейчас секции `[profile.release]` в воркспейсе нет, то есть действует `panic = "unwind"`; запрет фиксируется здесь, чтобы его не сняли ради размера бинарника.

**4. Взведение исключений ADR-0003 не требует ни одного нового метода порта.**

- **Raw Input курсора** уже полностью описан существующим `Effect::SetPointerTracking(bool)` → `PointerTracker::set_active(bool)`. Внутри адаптера: `RegisterRawInputDevices` с `RIDEV_INPUTSINK` при взводе и `RIDEV_REMOVE` при снятии, причём при `RIDEV_REMOVE` поле `hwndTarget` обязано быть **NULL**, иначе вызов провалится и подписка тихо останется — то есть ADR-0003 будет нарушен молча.
- **Фолбэк-опрос 500 мс** — целиком внутри адаптера `LayoutMonitor`. Решение о взводе принимается на **уже существующей** подписке `EVENT_SYSTEM_FOREGROUND`, то есть «решить, опрашивать ли» само не стоит ни одного опроса. Классификация переднего окна — лестница, fail-safe в сторону взвода при любой неопределённости: мёртвое окно и наше собственное окно состояние не меняют; известные «слепые» классы окон (консоль, ApplicationFrameWindow и т. п.) взводят; затем `OpenProcess(PROCESS_QUERY_INFORMATION)` — отказ `ERROR_ACCESS_DENIED` означает непрозрачный процесс (взвод), а при успехе `GetPackageFullName` различает упакованное приложение (взвод) и обычное desktop (снятие).

  Два факта, которые пришлось исправить относительно первоначальной идеи: `PROCESS_QUERY_LIMITED_INFORMATION` **непригоден** как пробник — Microsoft документирует это право как намеренно ослабленное подмножество, доступное даже к protected processes; а `IsImmersiveProcess` в windows-0.62.2 сгенерирована как `BOOL → Result<()>`, поэтому `Err` неотличим от «не immersive» — отсюда выбор `GetPackageFullName` с его однозначным трёхзначным ответом.

Наблюдаемость снятия — три слоя по возрастанию неподделываемости: (1) `LayoutSource::ForegroundPoll` не должен появляться в логе при обычном Win32-окне — проверка уже в системе типов; (2) `info!` ровно на взвод и на снятие, счётчик тиков печатается только в строке снятия, сам тик — `trace!`, поэтому простой даёт ноль лог-трафика; (3) счётчик переключений контекста на потоке раскладки (`typeperf`/Process Explorer) — живой `SetTimer` на 500 мс даёт ~2 переключения в секунду, снятый — ноль. Третий слой наше собственное логирование подделать не может.

## Рассмотренные альтернативы

- **`Event::CapabilityChanged` + `Effect::ShowCapabilityWarning` в ядре.** Отклонено: ядро получило бы список OS-ных имён возможностей и тесты, проверяющие только проброс.
- **Отдельный канал `Receiver<CapabilityReport>`.** Отклонено: удваивает проводку и теряет порядок относительно `LayoutChanged`.
- **Оставить `PlatformError(String)` и парсить текст в оболочке.** Отклонено: парсинг человекочитаемых строк — это OS-знание в шелле плюс поломка при любой правке текста.
- **Оптимистичная запись конфига с корректировкой при отказе.** Отклонено: `PersistConfig` в том же батче, неверное значение успевает на диск.
- **Убрать `autostart` из конфига, читать реестр по требованию.** Отклонено: конфиг перестаёт быть самодостаточным для переноса и бэкапа.
- **Универсальный супервизор в `switcher-app` с фабрикой-замыканием.** Отклонено: колбэк через границу потока в порту; плюс оболочка не знает OS-специфичного setup потока.
- **Хелпер супервизии в `switcher-platform`.** Отклонено: замыкание-фабрика стала бы частью портовой поверхности.
- **Бесконечный retry без потолка.** Отклонено: спека требует, чтобы повторные падения **отключали** источник; бесконечный retry — тихая деградация без сообщения пользователю.
- **Порт `LayoutMonitor::set_fallback_poll(bool)`.** Отклонено: оболочка не знает и не должна знать, что такое «elevated foreground»; решение принимается там, куда приходит `EVENT_SYSTEM_FOREGROUND`.
- **Взводить опрос всегда «на всякий случай».** Отклонено: ровно то, чем продукт не хочет быть (ADR-0003).

## Последствия

- **Ни один трейт-порт не приобрёл нового метода** — полный контракт деградации стоит портам только новых типов данных, а ядру — одного нового `Event`, одного нового `Effect` и одного переписанного теста. Тестов ядра становится 51 вместо 42: один тест автозапуска удалён, шесть добавлены (пять на автозапуск, один на дедуп звука), плюс правки конфига и контента из той же задачи. Единственный счётчик тестов — задача 8 плана; сверять по ней, а не по этой строке.
- `switcher-app` приобретает `CapabilityMap`, обработчик `CapabilityChanged`, компоновщик тултипа и меню, исполнитель `Effect::SyncTrayMenu` и сверку автозапуска на старте.
- `switcher-windows` приобретает внутренний `supervise.rs` и фичи `windows`: `Win32_System_Threading`, `Win32_System_Registry`, `Win32_UI_Accessibility`, `Win32_UI_Input`, `Win32_UI_Input_KeyboardAndMouse`, `Win32_Storage_Packaging_Appx`, `Win32_Globalization`.
- Спека «показывает причину в настройках/трее» в M1 выполнена **наполовину**: трей есть, окна настроек нет (оно в M2 по дорожной карте). Формулировать в отчёте о M1 именно так.
- `CapabilityReport.detail` — английская строка от адаптера, тогда как меню трея русское. Осознанный компромисс M1; правильное решение (таблица `code -> локализованная строка` в оболочке) — M2 вместе с окном настроек.
- Честно отложено в M2: повторное включение выключенного источника без перезапуска приложения («Повторить» в трее); панель возможностей в настройках; супервизия потока оверлея (его состояние — видимый бейдж — пришлось бы восстанавливать реплеем эффектов).
- Обнаружение «источник жив, но не стреляет» (например, если `HSHELL_LANGUAGE` окажется мёртвым на Windows 11) требует состояния с таймаутом, то есть нового взводимого исключения — и потому **не входит в M1**. В M1 мёртвый источник просто тихо не даёт событий, а корректность держат остальные два плюс фолбэк-опрос.
- Асимметрия сохранена сознательно: `PersistConfig` = «сохранить и пересинхронизировать галки», `SyncTrayMenu` = «только пересинхронизировать». Сужение `PersistConfig` до «только сохранить» сломало бы шесть тестов ядра ради косметики.
- Константы 250/1000/4000 и 60 с — инженерное суждение, не выведенное из документации; проверяются эмпирически (убить `explorer.exe` и замерить восстановление shell-hook) и правятся осознанно.
