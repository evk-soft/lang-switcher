# 0006. Бейдж растеризует оболочка в premultiplied BGRA, с ленивым кэшем по (контент, DPI)

Дата: 2026-08-25. Статус: accepted.

## Контекст

Между ядром и портом оверлея разрыв: ядро отдаёт `Effect::ShowBadge { content: BadgeContent, .. }` — логическое описание (метка «RU», цвета, стиль), а `OverlayWindow::show` требует уже растеризованный `BadgeImage`. Никто не производит `BadgeImage`: растеризатора в проекте нет. При этом overview.md обещает бейджи, пререндеренные под язык и масштаб, ADR-0004 требует вывода через `UpdateLayeredWindow`, а NFR ограничивают бинарник 1–4 МБ и RSS 5–15 МБ.

Отдельный, неочевидный, но критичный вопрос — байт-порядок: контракт `BadgeImage` был объявлен как `rgba_premul`, и это имя нельзя было проверить, пока адаптера не существовало.

## Решение

**Растеризация живёт только в `switcher-app/src/render.rs`** — чистая функция без вызовов ОС, без окна, без GDI, тестируемая на любой ОС:

```rust
pub struct BadgeKey { pub content: BadgeContent, pub dpi: u32 }   // всё, что меняет пиксели
pub fn render_badge(font: &FontRef<'_>, key: &BadgeKey, metrics: &BadgeMetrics)
    -> Result<BadgeImage, RenderError>;
pub struct BadgeCache { /* font, metrics, HashMap<BadgeKey, BadgeImage> */ }
```

Конвейер (все вызовы сверены с исходниками tiny-skia 0.12.0 и ab_glyph 0.2.32): `Pixmap::new` → путь скруглённого прямоугольника через `PathBuilder` (готового rounded-rect в tiny-skia 0.12 **нет**, проверено) → `fill_path` фоном → `Mask::new` + `OutlinedGlyph::draw` покрытием глифов → тот же путь заливается цветом текста **через маску**, отчего чернила не могут вылезти за скруглённую форму → swap каналов → `BadgeImage`.

**Формат пикселей: premultiplied BGRA, и поле называется `bgra_premul`.** Обоснование цепочкой проверенных фактов:

| Звено | Формат |
|---|---|
| `tiny_skia::Pixmap::data()/take()` | premultiplied, порядок байт **RGBA** (док-комментарий крейта) |
| 32bpp `BI_RGB` DIB для `UpdateLayeredWindow` | DWORD `0x00RRGGBB`; на little-endian байты — **B, G, R**, старший байт при `AC_SRC_ALPHA` = alpha ⇒ **BGRA** |
| Премультипликация | требуется обоими: `AC_SRC_ALPHA` документирован как «values must be premultiplied with the alpha» |

Значит нужна ровно одна операция — `swap(0, 2)` по каждому пикселю, **без** демультипликации (`Pixmap::take_demultiplied()` использовать нельзя). Операция принадлежит `render.rs`, а не адаптеру: кэш обязан хранить байты, готовые к `copy_from_slice`, иначе swap исполнялся бы на каждый показ вместо каждого промаха кэша, и дублировался бы в каждом адаптере. Stride 32bpp DIB равен `width * 4` без выравнивания, поэтому адаптер делает прямое копирование, а `biHeight = -height` даёт top-down DIB, совпадающий с контрактом.

Имя поля — не косметика: это единственная защита от того, что следующая реализация поверит ему и получит синие «RU» вместо красных.

**Иконка трея — второй, отдельный растеризатор со straight alpha.** `tray_icon::Icon::from_rgba` строит AND-маску из `a.wrapping_sub(255)` и сам переворачивает каналы в BGRA, то есть ожидает **не**премультиплицированный RGBA. Передать туда премультиплицированный буфер — получить тёмную кайму по краям иконки. Два формата в одном приложении — осознанная цена, зафиксированная здесь: `BadgeImage` (premultiplied BGRA) идёт только в `OverlayWindow::show`, иконка трея через порт вообще не проходит.

**Кэш** — `HashMap<BadgeKey, BadgeImage>` в `switcher-app`, владелец — структура рантайма главного цикла. Ключ исчерпывает входы, меняющие пиксели: все поля `BadgeContent` (метка, фон, текст, стиль) плюс `dpi`. Метрики в ключ не входят — они константны в пределах процесса. Ёмкость: при 96 dpi бейдж ≈ 4 КБ, при 384 dpi ≈ 68 КБ; реалистично ≤ 12 записей (4 языка × 3 масштаба). Вытеснение — `clear()` при достижении `MAX_ENTRIES = 16`: LRU не окупает зависимость, промах стоит один рендер меньше миллисекунды. Дополнительно `clear()` вызывается при исполнении `Effect::PersistConfig`, чтобы мёртвые записи от старой палитры не накапливались (гигиена памяти, не корректность).

Заполнение — ленивое, а не eager на старте: набор языков и DPI известен только в рантайме, а NFR требует мгновенного старта.

**Шрифт** встраивается `include_bytes!` как статический (не variable) инстанс, сабсет A–Z + `?` + 0–9, рядом кладутся текст лицензии и `README.md` с точной командой сабсеттинга и версией исходного шрифта. Для всех BCP-47-тегов, которые отдаёт ОС, метка получается ASCII-uppercase, поэтому сабсета достаточно, включая `"??"` для пустого lang-tag. Гарантии в коде нет: `to_ascii_uppercase` не-ASCII символы пропускает как есть, так что теоретически возможную не-ASCII метку закрывает откат на сплошной swatch (см. ниже). Конкретный шрифт и его лицензия выбираются в задаче реализации **после** чтения вложенного файла лицензии, а не по памяти, и фиксируются отдельным ADR.

**Устойчивость:** если для метки не получилось ни одного ink-пикселя (нелатинский subtag → нет глифа), функция откатывается к сплошному цветному swatch. Пустой бейдж невозможен.

## Рассмотренные альтернативы

- **Растеризация в `switcher-windows` через D2D/DirectWrite или GDI.** Отклонено: тянет unsafe и COM в путь рендера, ломает изоляцию платформы, делает бейдж непроверяемым unit-тестом.
- **Растеризация в `switcher-core`.** Отклонено: `tiny-skia`/`ab_glyph` — графика в домене; ядро обязано остаться без графических зависимостей.
- **Swap R↔B в адаптере.** Отклонено: исполнялся бы на каждый показ, а не на каждый промах кэша, и дублировался бы в каждом OS-адаптере.
- **Оставить имя `rgba_premul` и «помнить» про swap.** Отклонено: имя поля — часть контракта порта; неверное имя гарантированно даст перевёрнутый канал.
- **`take_demultiplied()` перед отдачей.** Отклонено: `AC_SRC_ALPHA` требует именно premultiplied; демультипликация сломала бы композицию и добавила потери округления.
- **Вшитые PNG вместо рантайм-рендера** (вариант из ADR-0004). Отклонено: цвета настраиваются через `badge.colors`, DPI бывает произвольным — заготовить все комбинации нельзя; плюс PNG возвращает `png-format` и шесть транзитивных крейтов.
- **Пререндер всех бейджей на старте.** Отклонено: набор языков и DPI известен только в рантайме, а старт должен быть мгновенным.
- **LRU-кэш отдельной зависимостью.** Отклонено: 16 записей по ≤ 68 КБ, промах меньше миллисекунды.
- **Добавить `dpi` в `Effect::ShowBadge`.** Отклонено: ядро узнало бы про физические пиксели, и это единственная альтернатива, ломающая существующие тесты ядра — шесть тестов с литералом `ShowBadge` (хелпер `default_content` при этом уцелел бы: он возвращает `BadgeContent`, а не эффект).
- **Один общий растеризатор для бейджа и иконки трея.** Отклонено фактически: у них разные требования к альфе (premultiplied против straight), общий код дал бы тёмную кайму в трее.

## Последствия

- `BadgeImage.rgba_premul` переименовывается в `bgra_premul` (плюс поле `dpi` из ADR-0005). Тестов ядра это не ломает: `BadgeImage` в `switcher-core` не упоминается вообще.
- `Rgb8` и `BadgeStyle` получают `Hash` (`Eq` у них уже выведен — повторный в том же `derive` был бы `E0119`), `BadgeContent` — `Eq + Hash`. Всё аддитивно, ни один тест не ломается: они становятся частью ключа кэша.
- `switcher-app` приобретает `thiserror` (для `RenderError`) и бинарный артефакт-шрифт в `assets/fonts/`, а вместе с ним лицензионное обязательство: текст лицензии шрифта, а также лицензии `tiny-skia` (BSD-3-Clause) и `ab_glyph` (Apache-2.0) попадают в файл сторонних лицензий при упаковке.
- Фичи урезаются (см. ADR-0008): `tiny-skia` без `png-format`, `ab_glyph` без `variable-fonts` — вместе это выкидывает из графа `png`, `flate2`, `miniz_oxide`, `fdeflate`, `crc32fast`, `adler2` и `simd-adler32`. На Windows `png` тянет только `tiny-skia`: у `tray-icon` и `muda` он под `cfg` других ОС.
- Тесты рендера утверждают **инварианты**, а не golden-байты: размер по DPI, alpha угла = 0, центральный пиксель = `[bg.b, bg.g, bg.r, 255]`, `b<=a && g<=a && r<=a` для всех пикселей (проверка премультипликации), непустое множество пикселей цвета текста. Побайтовая детерминированность между сборками (разные `target-feature`, `simd`, версии растеризатора глифов) **не гарантируется** и golden-тестами не проверяется.
- Остаётся открытым и решается на первом mixed-DPI прогоне: округление размеров при нецелых DPI (например 110) может дать «дрожащую» на 1 px высоту. Если это проявится — `dpi` в ключе квантуется до ближайших 25 %.
- `tiny_skia::Pixmap::fill_path` тихо выходит, если bounds пути почти нулевые, поэтому нужен тест на нижней границе (96 dpi, стиль `Color`).
- Метрики бейджа (высота, минимальная ширина, паддинг, радиус, размер текста) — дизайн-предложение, а не проверенный факт; подтверждаются глазами на 100 %/150 %/200 % и после этого фиксируются константами.
