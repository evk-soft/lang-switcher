# 0019. Резервное чтение раскладки каждые 200 мс включается из трея

Дата: 2026-09-08. Статус: accepted.

## Контекст

Ручные проверки выявили недоставку Shell/TSF в обычном Win32-окне. Прежняя
политика снимала там резервный таймер, оставляя устаревший бейдж без следующего
чтения. В эксперименте с Terminal все восемь введённых а/f совпали с Win32 HKL,
но адресный TSF getter всегда показывал EN. Это не доказывает исправление
прежних пропусков Terminal: нужен контроль полного приложения без этого getter.

Пользователь разрешил резервную проверку 200 мс и попросил включение/отключение
через трей. Решение заменяет Windows-исключение ADR-0003 и классификацию
foreground из раздела 4 ADR-0007; остальные положения этих ADR сохраняются.

## Решение

- TOML `[layout] fallback_enabled = true` по умолчанию, включая старый конфиг
  без нового поля. Галка «Резервная проверка раскладки» меняет настройку сразу
  и сохраняет её. Значение — намерение пользователя, отказ адаптера отражается
  отдельно в состоянии/предупреждении, как у звука.
- Новый метод порта `LayoutMonitor::set_fallback_enabled(bool)` передаёт
  настройку владельцу message loop. Последнее значение сохраняется между
  попытками супервизора. Сохранённый false передаётся при создании адаптера:
  при старте не возникает кратковременного включения таймера.
- При включённой опции таймер 200 мс взводится для любого валидного чужого
  foreground. Собственное окно и отсутствие foreground снимают его, если
  доступен foreground hook, который снова взведёт таймер при смене окна.
- Если foreground hook установить не удалось, включённая опция сохраняет
  таймер также для поиска нового foreground. HKL читается только для валидной
  чужой пары HWND/TID. Это дополнительный явно ограниченный режим деградации:
  отказ подписок не отключает резервный путь.
- Выключение опции полностью снимает резервный таймер, в том числе в Terminal,
  elevated и UWP. Shell/foreground/TSF подписки продолжают работать. Уже
  находящиеся в очереди ForegroundPoll игнорируются выключенным runtime.
- Каждое чтение привязано к повторно проверяемой паре HWND/TID. Нулевой TID
  не выбирает собственную раскладку. OpenProcess и GetPackageFullName из
  частого пути удаляются: тип процесса больше не определяет право на опрос.
  Общий reader также отклоняет собственный процесс при потреблении отложенного
  события: открытие меню трея не подменяет чужую раскладку раскладкой нашего
  скрытого окна. Такой отказ сохраняет бейдж без звука и предупреждения.
- Подписки ускоряют реакцию, но первый callback не отключает резервный путь.
  Дедупликация остаётся в ядре после свежего чтения runtime: подавление
  уведомлений в адаптере могло бы потерять исправление устаревшего состояния.
- Управляющий bool и отзываемый PumpWaker защищены одним mutex. Отзыв
  выполняется до выхода потока; параллельный setter не пишет в переиспользованный
  TID. Неограниченной очереди управляющих команд нет.
- Ошибка создания/удаления таймера прекращает публикации текущей попытки и
  передаётся супервизору. Окно уничтожается вместе с принадлежащим ему таймером.

## Рассмотренные альтернативы

- Сохранить только события: уже наблюдалась недоставка при неизменном foreground.
- Ввести глобальный WH_SHELL через DLL: дополнительные ограничения разрядности,
  доставки в защищённые приложения и влияние на чужие процессы.
- Читать только после клавиатурной комбинации: не покрывает переключение через
  интерфейс или другой программой.
- Адресный TSF getter: Microsoft помечает его «Should not be used», а в проверке
  он не отразил реальные смены языка.

## Последствия и проверка

При включённой опции в активном чужом окне есть до пяти номинальных тиков в
секунду; прежнего обещания отсутствия пробуждений Windows layout-потока больше
нет. CPU/память измеряются на новой release-сборке с включённой и выключенной
опцией. Audio/pointer/tray таймеры этим решением не добавляются.

200 мс — период WM_TIMER, не гарантия задержки под нагрузкой. Переход A→B→A
между чтениями может быть пропущен. Нужны регрессии конфигурации/дедупликации,
применения опции из трея и сохранения, защиты от queued ticks, native
arm/disarm/rearm, а затем контроль полного приложения с обычным Win32 и Terminal.
