# Простой M1: измерения и незакрытые требования

Дата: 2026-09-07. Сборка: release, код задачи 20 (`eed318f`), Windows 11
Enterprise 10.0.26200, Rust 1.96.1. Профиль сборки не менялся.

**Продолжение 2026-09-08:** постоянная работа аудио и hover-таймер устранены,
очередь логгера уменьшена. Новые замеры и оставшиеся ограничения —
в [отчёте об исправлениях](2026-09-08-idle-fixes.md). Ниже сохранён исходный срез,
включая формулировки открытых на 2026-09-07 замечаний.

## Метод и результат

Запуск `lang-switcher.exe --data-dir target/m1-release-idle-2026-09-07 --run-for 620`.
Отдельный конфиг: `log_level='info'`, `[sound] enabled=false`, остальное по умолчанию.
Аудиоустройство при этом открывается. Рабочий стол пользователя продолжал работать;
конкретное foreground-окно и конфигурация мониторов не фиксировались.

После 5 секунд прогрева собран 61 снимок с шагом около 10 секунд:
`Process.Refresh()`, `TotalProcessorTime`, `WorkingSet64`, `PrivateMemorySize64`,
количество потоков/дескрипторов. CPU = `100 × ΔCPUSeconds / ΔwallSeconds`,
без деления на число ядер. Это доля одного логического CPU. Размер лога читался
через открытый FileStream с FileShare.ReadWrite: каталог Windows может выдавать
устаревший размер ещё открытого файла, поэтому одного FileInfo.Length недостаточно.

## Подтверждённая работа звука в простое

В отдельном 20-секундном срезе поток 55072 потребил 0,09375 секунды CPU; остальные
измеренные потоки — 0. Его имя `cpal_wasapi_out` прочитано через
[GetThreadDescription](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getthreaddescription).
Это подтверждает источник работы на данном интервале, но не приписывает аудио
каждый пик всего прогона или весь рабочий набор памяти.

Исходники зафиксированных зависимостей объясняют поведение:

- `startup.rs` всегда открывает SoundDevice, включая disabled-конфиг.
- rodio 0.22.2, `src/stream.rs`: `MixerDeviceSink::open` вызывает `stream.play()`;
  callback обходит каждый выходной сэмпл даже при пустом микшере.
- rodio, `src/mixer.rs`: пустой MixerSource проверяет очередь на каждом frame.
- cpal 0.17.3, `src/host/wasapi/stream.rs`: поток ждёт audio-ready event и
  обслуживает буферы. Это периодическая работа аудиоустройства, не таймер ядра.

**Требуется доработка до закрытия NFR.** Минимальное отключение sink при
`enabled=false` должно поддерживать последующее включение из трея, обновление
доступности и сохранение пользовательского предпочтения при ошибке устройства.
Однократная подстановка NullSoundPlayer при старте этому контракту не соответствует.

Для простоя с `enabled=true` нужен управляемый pause/resume либо создание потока
на период воспроизведения. У MixerDeviceSink нет публичного pause; потребуется
обоснованное изменение владельца потока или зависимости. Завершение генерации
сэмплов не равно окончанию аппаратного воспроизведения, поэтому произвольный
sleep на 90 мс с последующим Drop может отрезать звук. Принятое решение нужно
зафиксировать ADR и проверить на устройстве; в текущем коммите оно не подменено
непроверенной оптимизацией.

## Дополнительный дефект зависимости: hover-таймер трея

Read-only ревью обнаружило путь в tray-icon 0.24.1,
`src/platform_impl/windows/mod.rs`, строки 478–529:

1. Движение внутри иконки включает SetTimer с периодом 15 мс.
2. Первый WM_TIMER извлекает `last_position.take()`.
3. Если курсор ещё внутри иконки, таймер не удаляется, а last_position уже None.
4. Следующие тики ничего не делают и не удаляют таймер.

Это подтверждённый путь по коду зависимости; воспроизведение через настоящий
hover и отдельный замер пробуждений main пока не выполнены. В нашем срезе main
не расходовал CPU, поэтому этот дефект не объявляется причиной измеренных пиков.

Дефект **остаётся открытым**, не отклонён ревью. Нужна native-регрессия «движение →
неподвижный курсор внутри → уход», затем исправленная зависимость либо явно
проверенное отключение ненужных Enter/Move/Leave с сохранением кликов и меню.
Нельзя полагаться на частный номер таймера без фиксации версии и ADR.

## Следующая проверяемая работа

1. Исправить аудио lifecycle с тестами включения/выключения без перезапуска,
   потери устройства, быстрых RU/EN и конца тона. Сравнить disabled и enabled idle.
2. Воспроизвести и исправить hover-таймер; замерить main до/после наведения.
3. Повторить CPU с шагом 5 с, память после 20 смен раскладки и 5 минут работы,
   лог за 10 минут неизменного foreground. Порог памяти не повышать без решения;
   PrivateBytes не выдавать за WorkingSet и не уменьшать набор принудительно ради замера.
4. Пройти ручную матрицу детекции/звука/оверлея в smoke-чеклисте.

M1 не считается принятым до закрытия этих пунктов либо явного пересмотра требований.
