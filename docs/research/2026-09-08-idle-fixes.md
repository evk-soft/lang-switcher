# Аудио, таймер трея и память логгера: продолжение аудита

Дата: 2026-09-08. База `be46ff1`, основная папка проекта, без worktree.
Windows 11 Enterprise 10.0.26200; release Rust 1.96.1, профиль сборки не менялся.
Предыдущие измерения сохранены в [отчёте 2026-09-07](2026-09-07-idle-performance.md).

**Позднейшее наблюдение 07:40 UTC:** fixture получила foreground и выполнила 20
смен RU/EN, но приложение не обнаружило их. Это блокер доставки M1, причина
ещё не установлена. [Отдельный отчёт и диагностика](2026-09-08-layout-delivery.md).
Ниже сохранены результаты аудио/ресурсов и состояние до этого ручного прогона.

## Исправления

1. rodio/cpal заменены прямым WASAPI. PCM синтезируется без устройства; отдельный
   STA открывает stream только на время сигнала и освобождает его после drain.
   В простое нет аудиотаймера и генерации тишины. Один заменяемый слот ограничивает
   накопление подсказок, stop не зависит от живых копий sender. Подробности и API:
   [ADR-0016](../architecture/adr/0016-demand-driven-wasapi-cues.md).
2. Первый STA принадлежит main и закрывается после дочерних audio/TSF. При
   фатальном таймауте shutdown guard сохраняется до завершения процесса. Ошибка
   создания аудиопотока сохраняет исходный код, не переименовывается в отказ устройства.
   Дополнительно устранена гонка play/stop: mutex защищает и замену PCM, и завершение
   PostThreadMessage, поэтому join не может освободить TID до последнего wake.
   Детерминированная регрессия с каналами воспроизвела RED и прошла после исправления.
3. Закреплён минимальный патч tray-icon 0.24.1: создание с hover_tracking=false
   отключает Enter/Move/Leave и их таймер. Кликовые обработчики сохраняются.
   Исходники/лицензии/происхождение — vendor/tray-icon, решение —
   [ADR-0017](../architecture/adr/0017-disable-unused-tray-hover.md).
4. Очередь tracing-appender уменьшена с 128 000 до 1024 строк. Исходный bounded
   channel резервировал около 4 МиБ даже при пустом логе. Lossy-режим сохранён:
   при переполнении строки отбрасываются, native callbacks не блокируются.

## Нативные проверки

`cargo run --release -p switcher-app --example audio_smoke`: 20 беззвучных буферов
по 3969 PCM16-сэмплов прошли через реальное устройство. После каждого active=false,
started=completed; до первого и после последнего сигнала воспроизведения нет.
Первый сигнал с предварительным Initialize без Start завершился за 271 мс,
весь диапазон — 271–325 мс, включая создание, 90-мс данные, latency-tail и teardown.
Это время полного завершения, не измерение задержки до первого слышимого сэмпла.
Запрос следующего сигнала, ожидание active и Drop с живым sender заняли вместе
200 мс; отправка отозванным sender не возобновила поток. Exit 0.
Прослушивания и физического отключения/возврата устройства в этом тесте не было.

Финальный повтор после синхронизации play/stop (07:30 UTC): снова 20/20, active=false
после каждого буфера, exit 0. Полное завершение 126–157 мс, этап stop с живым sender
41 мс. Между прогонами задержки устройства различались; фиксированной гарантией
latency эти числа не являются. Финальный release после этой правки — 2 858 496 байт;
длинные ресурсные замеры ниже выполнены до неё, при неизменной работе в простое.

`cargo run -p switcher-windows --example tray_smoke`: RED/GREEN на том же сценарии.
До native-исправления оба режима дали 1 WM_TIMER, 3 hover-события, 2 клика.
После: hover=true — 1/3/2, hover=false — 0/0/2. Это фактические сообщения собственной
очереди, не только проверка boolean. Explorer должен выдавать координаты значка:
для прогона временно раскрыта панель скрытых значков через UI Automation, затем
её состояние восстановлено. Сам harness не меняет курсор/фокус. Upstream-дефект
режима hover=true не исправлялся: приложение явно отключает ненужный механизм.

Независимое read-only ревью проверило native ownership, COM, очереди, ожидания,
точность vendor-diff и логгер. Замечания исправлены; подтверждённых блокеров нет.
Workflow `rust-adversarial-review` недоступен; это замена ревью, не его запуск.

## Ресурсы

Метод: отдельный config.toml, INFO, sound.enabled=false; аудиосервис всё равно
проходит probe и ожидает команды. После прогрева — Process.TotalProcessorTime,
WorkingSet64, PrivateMemorySize64 и размер открытого лога с FileShare.ReadWrite.
CPU — доля одного логического ядра, без деления на число ядер. Интервал около 10 с.
Это рабочий desktop с внешними сменами foreground, а не изолированные 10 минут
неподвижного окна. Длительность и рост лога не скрывают это ограничение.

| Метрика | WASAPI, прежняя очередь логов | WASAPI, очередь 1024 |
|---|---:|---:|
| Продолжительность приложения | 620 с | 320 с |
| Интервал снимков | 611,90 с | 310,98 с |
| Средний CPU | 0,0255% | 0,0201% |
| Максимум интервала около 10 с | 0,4679% | 0,1559% |
| WorkingSet после 5 минут | 21 745 664 байта = 20,74 МиБ | 17 690 624 байта = 16,87 МиБ |
| PrivateBytes после 5 минут | 6 922 240 байт | 2 842 624 байта |
| Прирост INFO-лога | 2418 байт, были показы/смены foreground | 270 байт; до первого показа 280,90 с без роста |
| Release EXE | 2 862 592 байта | 2 862 592 байта |

Оба приложения завершились сами: exit 0, stderr пуст, финальный clean=true.
Уменьшение WorkingSet на сопоставимом пятиминутном снимке — 4 055 040 байт,
около 3,87 МиБ. Во втором прогоне WorkingSet был 16,48–16,87 МиБ.

Для сравнения: предыдущий rodio-прогон дал 0,385% среднего CPU и 1,243% максимума
на первых 421,64 с без показов. Условия не полностью совпадают; новый замер
подтверждает существенное снижение, но не подменяет контролируемую матрицу NFR.
Рабочий набор не уменьшался искусственно через EmptyWorkingSet/trim.

Read-only QueryWorkingSetEx до изменения логгера: резидентные страницы модулей
15 478 784 байта, из них допускающие разделение — 14 508 032. Остальное включает
heap/stacks и прочие mappings. Shareable не означает, что страницы фактически
разделены сейчас, и не заменяет WorkingSet. Это объясняет, почему уменьшения
очереди недостаточно для достижения 15 МБ на данном Windows.

Локальные артефакты: target/m1-idle-wasapi-20260908-095808,
target/m1-idle-wasapi-20260908-101225, target/resident-modules.json.
Код диагностик аудио/трея сохранён в examples; target игнорируется Git.

## Что остаётся открытым

- Память выше исходной цели 5–15 МБ. Порог не пересмотрен; PrivateBytes не выдаётся за RSS.
- Отказ/восстановление физического аудиоустройства и субъективное качество тонов.
- Доставка RU/EN в Win32/elevated/packaged/Terminal, визуальное поведение/DPI,
  интерактивное меню/Explorer и настоящий автозапуск после входа.
- 20 смен раскладки с последующим замером: автоматические fixture-прогоны
  не получили устойчивого foreground и остановились до первого перехода.
  Ручная попытка также истекла без активации окна; успешной доставки это не доказывает.

Добавлен `cargo run --release -p switcher-windows --example layout_driver`:
собственное окно с EDIT, только уже установленные RU/EN, ожидание ручной активации
до 30 с, 20 переключений за ~13 с, остановка при потере foreground. Клавиши в чужие
окна не посылаются; после завершения восстанавливается прежний фокус, если он
ещё на fixture. Нужен параллельно запущенный app или layout_smoke для проверки доставки.

platform 3, windows 56, overlay-example 1) и Rust 1.87. Финальный пятисекундный
запуск с enabled=true, volume=0: PMv2 из манифеста, audio_ready, exit 0, stderr
