# Короткий сигнал завершался до достижения конца по счётчику устройства

Дата: 2026-09-08. Windows 11, `Speakers (3- Realtek(R) Audio)`.
Пользователь подтвердил выбранный endpoint снимком: громкость 88%.
Это тот же выход, что и в [предыдущей диагностике](2026-09-08-user-manual-check.md).

## Различающий эксперимент

`audio_compare` использует исходный production-синтезатор и WASAPI stream через
`#[path]`, без копии алгоритма воспроизведения. A проходит через обычный worker
и его bounded mailbox. B/C/D/E вызывают тот же stream напрямую, поскольку
длительность B/C/D превышает публичный лимит подсказки 200 мс.

| Вариант | Содержимое | Исходный backend: наблюдение |
|---|---|---|
| A | обычный RU, 90 мс, через worker | padding=0 при clock 5666/88200=64 мс; endpoint peak до/во время/после = 0 |
| B | те же 90 мс + 1 с тишины | endpoint peak 0.471653 |
| C | 1 с тишины + те же 90 мс + 1 с тишины | endpoint peak 0.395565 |
| D | непрерывный 660 Гц, 2 с | endpoint peak 0.498327 |
| E | те же 90 мс, прямой stream | padding=0 при clock 6200/88200=70 мс; peak во время 0, после закрытия 0.482267 |

Артефакты A–D: `target/audio-compare-run-20260908-121205369`;
E: `target/audio-direct-short-20260908-121354648`.
PCM пиковый отсчёт A/B/C/E = 12268, D = 13107. `GetStreamLatency=0`,
capacity=1036; громкость сессий 1.0/unmuted, endpoint 0.88/unmuted.
Все процессы завершились с exit 0, stderr пуст.

Пользователь ответил на вопрос о первой серии A–D: **«Слышал короткие и длинный»**.
Это подтверждает слышимость сравнительной серии, но не определяет, какой именно
из трёх коротких вариантов был слышен, и не подтверждает отдельную серию после фикса.

WAV-файлы `target/audio-compare-prepare-20260908-121139772` независимо прочитаны
через Python `wave`: PCM16 mono 44100, длительности 0.09/1.09/2.09/2.0 с.
Побайтово проверено, что короткий PCM внутри A/B/C одинаков, а отличия B/C —
только добавленная тишина. В режиме `--prepare-only` аудио/COM не запускаются.
Файлы создаются через create_new, существующие файлы не перезаписываются.

Meter относится ко всему endpoint, не к конкретной сессии; никакой звук не
записывается. Нулевой baseline и совпадение по времени поддерживают связь
с тестовым сигналом, но не заменяют подтверждение слышимости. A/E различаются
путём вызова; прямой E нужен для отдельного сопоставления с B/C.

## Исправление

В пустой очереди WASAPI ещё может оставаться звук, не достигший заявленной
позиции устройства. Старое условие `all_frames_submitted && padding == 0`
ошибочно считало такой сигнал завершённым. Это подтверждено двумя разными
путями запуска, даже при возвращаемой GetStreamLatency=0.

[ADR-0018](../architecture/adr/0018-audio-device-playback-completion.md):
после очистки клиентской очереди дополнительно ждать конца по IAudioClock.
Сравнение учитывает собственную частоту clock и не округляет миллисекунды.
Постоянной тишины, произвольного секундного хвоста и таймера в простое нет.
Stop по-прежнему прерывает текущий сигнал, а watchdog ограничивает активный stream.

Два новых регрессионных теста воспроизвели ошибочное принятие позиции 64/70 мс
за конец 90-мс сигнала (RED), затем прошли после изменения условия (GREEN).
Отдельно проверены другие единицы clock, граничный отсчёт, нулевая частота
и большие значения без переполнения.

## Проверка изменения

- Native A и E после исправления:
  `target/audio-clock-check-20260908-121643941`. Оба завершились при
  position=7938/frequency=88200, то есть 90 мс; exit 0, stderr пуст.
  A peak до/во время/после = 0 / 0.001385 / 0.471636;
  E = 0 / 0 / 0.482269. После завершения приложения уровень может ещё
  отображаться — peak-meter публикует значения за предшествующий период.
- Рабочий `audio_smoke --audible` после исправления:
  `target/audio-clock-audible-20260908-121853579`. Все 20 коротких RU/EN
  достигли отметки 7938/88200, started=completed=20, active=false, exit 0,
  stderr пуст. Завершение с живым sender и активным тестовым stream — 186 мс.
  Пользователь отдельно подтвердил: эта последняя серия слышна, низкий и
  высокий тон различаются (ответ «да» на вопрос после исправления).
- fmt-check, Clippy all-targets `-D warnings`, workspace/all-targets tests и
  Rust 1.87 all-targets/locked прошли. 154 основных теста плюс 9 повторных тестов
  исходных модулей, включённых в audio_compare. Лог: `target/verification-audio-clock.txt`.
- Release приложения и примеры пересобраны. Размер приложения — 2 877 440 байт.
  Ресурсные замеры старых сборок не переименовываются в результаты новой.
- Независимое read-only ревью не нашло blockers в production-исправлении.
  В диагностическом примере по замечанию ревью ограничен drain сообщений
  128 сообщениями и добавлен выход по WM_QUIT. B–E обходят не только ограничение
  mailbox, но также worker/prewarm; это явно обозначено в комментарии примера.

Восстановление доставки раскладки при Win+Space/в Notepad++, повтор mixed-DPI
и остальные открытые пункты приёмки этим исправлением не закрыты.
