# Переводы

[English](translations.en.md) · [Установка](installation.ru.md) · [Настройки](settings.ru.md)

Два независимых набора переводов: интерфейс приложения и документация.

## Язык интерфейса

Формат — [Fluent](https://projectfluent.org/), по одному файлу `.ftl` на язык в
`crates/switcher-app/assets/i18n/`. Каталоги встраиваются в бинарник при сборке, поэтому
для нового языка нужна пересборка ([ADR-0021](../architecture/adr/0021-fluent-embedded-ui-catalogs.md)).

Сейчас поставляются: `en`, `ru`, `de`, `es`, `fr`, `zh-Hans`.

### Добавить язык

1. Скопируйте `assets/i18n/en.ftl` в файл с каноническим тегом языка, например `pt-BR.ftl`
   или `ja.ftl`. Регистр важен: язык строчными, письменность с заглавной, регион
   прописными — `zh-Hans`, `pt-BR`.
2. Переведите значения. **Идентификаторы слева от `=` не трогайте** и не удаляйте: набор
   идентификаторов должен точно совпадать с `en.ftl`.
3. Сохраните файл в UTF-8 без BOM.
4. Добавьте одну строку в массив `SUPPORTED` в
   [`crates/switcher-app/src/i18n.rs`](../../crates/switcher-app/src/i18n.rs):

   ```rust
   Locale {
       tag: "pt-BR",
       native_name: "Português (Brasil)",
       ftl: include_str!("../assets/i18n/pt-BR.ftl"),
   },
   ```

   `native_name` — название языка **на нём самом**: меню языков читает тот, кто ещё не
   понимает текущий язык интерфейса.
5. Запустите `cargo test -p switcher-app i18n`.

Больше править нечего. Подменю трея, подбор локали и проверка полноты берут язык из
`SUPPORTED` автоматически.

### Что проверяют тесты

- каждый каталог разбирается и загружается;
- набор идентификаторов совпадает с `en.ftl` — ни пропущенных, ни лишних;
- внутри каталога нет повторов;
- каждое сообщение, которое запрашивает код, есть в каждом каталоге;
- аргументы (`{ $label }`, `{ $names }`) подставляются;
- ни одно сообщение не пустое и не сводится к собственному идентификатору;
- тег канонический и переживает нормализацию в конфиге;
- названия языков не повторяются.

### Синтаксис Fluent, коротко

```ftl
# Комментарий.
menu-quit = Выход
tooltip-badge = lang-switcher · { $label }
```

Аргумент в фигурных скобках подставляется приложением. Его имя менять нельзя, а место в
строке — можно и нужно, если этого требует язык.

### Чего в каталогах нет

Ключи возможностей (`sound`, `layout.tsf`), коды ошибок адаптеров, поля логов и значения
конфига не переводятся. По ним ищут в логах и на них ссылаются отчёты об ошибках, поэтому
во всех языках они одинаковы.

### Заметки о подборе языка

- Запрошенный тег ищется точно, затем по языку и письменности, затем по одному языку.
  Поэтому `fr-CA` находит `fr`.
- Пока поставляется только `zh-Hans`, любое предпочтение китайского приводит к нему,
  включая `zh-TW`. Когда появится `zh-Hant`, для корректного разбора региональных тегов
  понадобятся данные CLDR о вероятных субтегах.
- Языки с письмом справа налево не поставляются и не проверялись. Одних возможностей
  Fluent для них мало: нужна проверка раскладки нативного меню Win32.

## Документация

Файлы в `docs/guide/` идут парами: `<имя>.ru.md` и `<имя>.en.md`. Верхняя строка каждого
файла ссылается на его пару.

Чтобы добавить язык, положите рядом `<имя>.<тег>.md` и добавьте ссылку в шапки остальных
файлов пары. `README.md` — русский, `README.en.md` — английский.

ADR и исследования в `docs/architecture/` и `docs/research/` ведутся только на русском:
это внутренний журнал решений, а не пользовательская документация.
