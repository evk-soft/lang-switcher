# lang-switcher

Лёгкий кроссплатформенный индикатор текущей раскладки клавиатуры (RU/EN): небольшой бейдж-флаг возле курсора мыши или текстовой каретки и опциональный звуковой сигнал при переключении — чтобы всегда было видно, на каком языке вы сейчас печатаете.

**Статус на 2026-09-08:** Windows-приложение собрано; fmt, Clippy и 179 тестов проходят, Rust 1.87 проверен. Резервная проверка раскладки каждые 200 мс теперь работает и в обычных Win32-окнах, включается/выключается из трея и сохраняется после перезапуска ([изменение и замеры](docs/research/2026-09-08-configurable-fallback.md)). Открытие собственного меню сохраняет последнюю раскладку редактора. Ранее исправлены постоянная работа аудио, hover-таймер трея, размер очереди логов и раннее закрытие короткого аудиосигнала ([проверка звука](docs/research/2026-09-08-audio-completion.md)).

**M1 ещё не принят:** пользователь подтвердил отображение RU/EN и слышимость/различие исправленных коротких сигналов, но сообщил о пропусках при Win+Space в Terminal и отсутствии смены бейджа в Notepad++ ([ручной прогон](docs/research/2026-09-08-user-manual-check.md), [диагностика доставки](docs/research/2026-09-08-layout-delivery.md)). Устранён пробел резервного пути обычных Win32-окон; полное приложение после изменения ещё требует проверки. Причина прежних пропусков Terminal отдельно не установлена. Цель памяти 5–15 МБ, остальные классы окон, визуальное поведение, звук при реальном переключении раскладки и настоящий автозапуск остаются открытыми. Состояние задач — в [плане M1](docs/superpowers/plans/2026-07-03-m1-windows-mvp.md), результаты — в [smoke-чеклисте](docs/smoke/m1-windows.md) и [аудите](docs/research/2026-09-07-implementation-audit.md).

## Ключевые требования

- Бейдж текущей раскладки у курсора мыши / текстовой каретки, поверх всех окон, «прозрачный» для кликов.
- Звуковая подсказка при смене раскладки (настраивается).
- Иконка в трее, автозапуск, около нуля CPU в простое, минимум RAM.
- Подписка на события ОС; на Windows — отключаемая резервная проверка каждые 200 мс. Windows 11 в первую очередь, затем macOS и Linux.

## Технология

Чистый нативный **Rust** (без webview): Cargo workspace с UI-независимым ядром и адаптерами под каждую ОС. Обоснование выбора — [аудит технологий](docs/research/2026-07-03-tech-audit.md) и [ADR-0001](docs/architecture/adr/0001-pure-native-rust.md).

| Крейт | Роль |
|---|---|
| `switcher-core` | домен: автомат раскладки, выбор якоря, модель конфига. Без OS-зависимостей, `#![forbid(unsafe_code)]` |
| `switcher-platform` | порты (traits) и плоские типы событий |
| `switcher-windows` | адаптеры Win32/COM — единственное место, где разрешён `unsafe` |
| `switcher-app` | оболочка: трей, главный цикл, растеризация бейджа, звук, wiring |

## Сборка и проверки

```sh
cargo build --workspace
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings   # должен быть чистым
cargo fmt --all -- --check
```

Запуск приложения: `cargo run --release -p switcher-app` или `target\release\lang-switcher.exe`.
Меню трея: постоянный показ, резервная проверка раскладки, звук, автозапуск, состояние и выход. В M1 доступны текстовый
бейдж и цветной квадрат; якорь-каретка и окно настроек относятся к M2.

Конфиг читается из `%APPDATA%\evk-soft\lang-switcher\config\config.toml` и создаётся
при первом сохранении настройки. Логи: `%LOCALAPPDATA%\evk-soft\lang-switcher\data\logs`,
по файлу на день UTC, сохраняются семь файлов. Уровень можно переопределить через
`LANG_SWITCHER_LOG`. Повреждённый или более новый конфиг не перезаписывается.

«Резервная проверка раскладки» включена по умолчанию. Галка применяется сразу и
сохраняется после перезапуска; ей соответствует настройка:

```toml
[layout]
fallback_enabled = true
```

При снятой галке приложение получает только уведомления Windows; если конкретное
окно их не доставляет, смена языка может остаться незамеченной до следующего события.

Для ограниченного диагностического запуска с отдельными данными:

```powershell
target\release\lang-switcher.exe --data-dir target\diagnostic --run-for 30
```

`--run-for` принимает 1–3600 секунд; без этого параметра приложение работает до выхода
через трей. Обычный запуск использует AppData, диагностический — указанный каталог.

Ручной прототип оверлея: `cargo run -p switcher-windows --example overlay_smoke`.
Он проводит через остановку для проверки кликов/DPI, перемещение между мониторами,
фиксированный угол и скрытый простой. Во время ожидания Enter изменения DPI обрабатываются.
Ожидания и ещё не проверенные пункты — в [smoke-чеклисте](docs/smoke/m1-windows.md).

Все три гейта обязательны перед коммитом (скил `quality-gates`) и продублированы в [CI](.github/workflows/ci.yml): гейты на Windows, отдельная проверка «ядро собирается и тестируется вне Windows» и джоб на MSRV.

Пошаговая ручная проверка из PowerShell 7: `.\scripts\manual-check.ps1`.
Скрипт разделяет прослушивание и переключения, включает постоянный бейдж,
оставляет приложение до выхода через трей и сохраняет ответы/журналы по этапам.
[Разбор предыдущего прогона и ограничения](docs/research/2026-09-08-user-manual-check.md).

Короткая проверка нового переключателя: `.\scripts\start-fallback-check.ps1`.
Она включает постоянный бейдж и звук в отдельном каталоге, запускает приложение
и независимый Win32-наблюдатель на 10 минут и печатает шаги проверки.
Повторный запуск с выведенным `-DataDir` сохраняет настройки для проверки перезапуска.
