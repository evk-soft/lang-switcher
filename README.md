# lang-switcher

Лёгкий кроссплатформенный индикатор текущей раскладки клавиатуры (RU/EN): небольшой бейдж-флаг возле курсора мыши или текстовой каретки и опциональный звуковой сигнал при переключении — чтобы всегда было видно, на каком языке вы сейчас печатаете.

**Статус на 2026-09-07:** собран резидентный Windows-бинарник с треем, общим рантаймом, оверлеем, Raw Input, тремя подписками на раскладку, звуком, конфигом и автозапуском. Проверены реальный запуск, чтение раскладки и штатное завершение; fmt, Clippy и 148 тестов проходят, совместимость с Rust 1.87 проверена. **M1 ещё не принят:** доставка переключений в разных приложениях, визуальное поведение и звук требуют ручного прогона; замеры CPU и рабочего набора памяти превышают целевые пороги. Аудио и hover-таймер трея требуют доработки ([разбор](docs/research/2026-09-07-idle-performance.md)). Состояние задач — в [плане M1](docs/superpowers/plans/2026-07-03-m1-windows-mvp.md), результаты — в [smoke-чеклисте](docs/smoke/m1-windows.md) и [аудите](docs/research/2026-09-07-implementation-audit.md).

## Ключевые требования

- Бейдж текущей раскладки у курсора мыши / текстовой каретки, поверх всех окон, «прозрачный» для кликов.
- Звуковая подсказка при смене раскладки (настраивается).
- Иконка в трее, автозапуск, около нуля CPU в простое, минимум RAM.
- Подписка на события ОС (без поллинга), Windows 11 в первую очередь, затем macOS и Linux.

## Технология

Чистый нативный **Rust** (без webview): Cargo workspace с UI-независимым ядром и адаптерами под каждую ОС. Обоснование выбора — [аудит технологий](docs/research/2026-07-03-tech-audit.md) и [ADR-0001](docs/architecture/adr/0001-pure-native-rust.md).

| Крейт | Роль |
|---|---|
| `switcher-core` | домен: автомат раскладки, выбор якоря, модель конфига. Без OS-зависимостей, `#![forbid(unsafe_code)]` |
| `switcher-platform` | порты (traits) и плоские типы событий |
| `switcher-windows` | адаптеры Win32/COM — единственное место, где разрешён `unsafe` |
| `switcher-app` | оболочка: трей, главный цикл, растеризация бейджа, звук, wiring |

## Сборка и проверки

```sh
cargo build --workspace
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings   # должен быть чистым
cargo fmt --all -- --check
```

Запуск приложения: `cargo run --release -p switcher-app` или `target\release\lang-switcher.exe`.
Меню трея: постоянный показ, звук, автозапуск, состояние и выход. В M1 доступны текстовый
бейдж и цветной квадрат; якорь-каретка и окно настроек относятся к M2.

Конфиг читается из `%APPDATA%\evk-soft\lang-switcher\config\config.toml` и создаётся
при первом сохранении настройки. Логи: `%LOCALAPPDATA%\evk-soft\lang-switcher\data\logs`,
по файлу на день UTC, сохраняются семь файлов. Уровень можно переопределить через
`LANG_SWITCHER_LOG`. Повреждённый или более новый конфиг не перезаписывается.

Для ограниченного диагностического запуска с отдельными данными:

```powershell
target\release\lang-switcher.exe --data-dir target\diagnostic --run-for 30
```

`--run-for` принимает 1–3600 секунд; без этого параметра приложение работает до выхода
через трей. Обычный запуск использует AppData, диагностический — указанный каталог.

Ручной прототип оверлея: `cargo run -p switcher-windows --example overlay_smoke`.
Он проводит через остановку для проверки кликов/DPI, перемещение между мониторами,
фиксированный угол и скрытый простой. Во время ожидания Enter изменения DPI обрабатываются.
Ожидания и ещё не проверенные пункты — в [smoke-чеклисте](docs/smoke/m1-windows.md).

Все три гейта обязательны перед коммитом (скил `quality-gates`) и продублированы в [CI](.github/workflows/ci.yml): гейты на Windows, отдельная проверка «ядро собирается и тестируется вне Windows» и джоб на MSRV.
